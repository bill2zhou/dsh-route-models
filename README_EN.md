A DeepSeek Harness (dsh) plugin that manages **account channels** for a dozen AI coding platforms in one place: browser login, account pools, daily check-in and credit claims, per-model switches. It also ships an OpenAI-compatible local gateway, a token-saving compaction pipeline, a usage dashboard and a per-request log.

Credentials go only to the host's credential store and private local files; the UI and API responses never echo them in clear text, and the plugin uploads no telemetry.

> A pure plugin: no core changes, no build step, no runtime dependencies. `llm` is the only hard dependency, so a composition without a web server (a headless terminal, for instance) still boots.

## What you get

Five tabs in the settings page, all about channels:

| Tab | Contents |
| --- | --- |
| **EAC router** (subtitle: 账号渠道) | Channel card grid: connect / manage, add an account, claim credits, daily auto check-in, model switches and reachability tests |
| **省 Token** | Tool-output compaction (RTK), two prompt-shaping families, five local answers, and byte-level savings statistics |
| **数据看板** | Today / lifetime tokens, input / output / reasoning / cache hits, time-to-first-token, decode speed, success rate, per-account and per-model breakdowns |
| **运行日志** | Per-request rows: outcome, duration, first token, speed, token split; failure reasons on hover; refreshed every 10 seconds |
| **网关设置** | The OpenAI-compatible gateway for channel models: switch, endpoint, API key, number of forwardable models |

Also included: an announcement center (live push plus OS notifications), a one-time usage notice and disclaimer (reopenable from the footer), and an optional visual-effects switch (off by default, stored in the current browser only).

## Account channels

Each card is one platform's account system:

| Channel | Vendor | Login | Credits / check-in |
| --- | --- | --- | --- |
| CodeArts | Huawei Cloud | browser | claim |
| WorkBuddy (CN) | Tencent | browser | claim + status |
| WorkBuddy (intl.) | Tencent | browser | status |
| LobsterAI | Youdao | browser | claim |
| Qoder | Alibaba | browser | claim |
| Qoder (CN) | Alibaba | browser | claim |
| TRAE | ByteDance | browser | claim |
| Loomy | iFlytek | SMS code | claim |
| Raccoon | SenseTime | browser | — |
| MiniMax Code | MiniMax | browser (device code + PKCE) | claim + status |
| ZCode | Zhipu | browser | claim (token unit) |

- Login runs in the browser: start it, wait for the callback, and the page finishes on its own. Nothing to copy or paste (10-minute ceiling).
- Credentials stay in the host's credential store; the page only receives the account list, state and usage. Clear text never leaves the host process.
- Each account can be enabled, disabled, removed and tested individually; models can be switched one by one or in bulk per channel.
- The channel pack is a community MIT implementation (see [vendor/channel-pack/NOTICE.md](vendor/channel-pack/NOTICE.md)), shipped with the plugin rather than downloaded later.

> The pack contains more provider implementations than the UI has cards (Cline and Gemini have implementations but no card). Models, quotas and login flows belong to each platform and can change at any time.

## Local gateway

The gateway page exposes channel models through an **OpenAI-compatible** endpoint:

```text
Base URL:  http://127.0.0.1:8326/v1
API Key:   shown / copied on the gateway page (generated by the pack on first enable)
Routes:    GET  /v1/models
           POST /v1/chat/completions      streaming and non-streaming
           POST /v1/responses
           POST /v1/reasoning-efforts
```

- The gateway binds loopback only. `DSH_OPENAI_GATEWAY_PORT` changes the port, `DSH_OPENAI_GATEWAY_ENABLED=0` disables it, and `DSH_OPENAI_GATEWAY_API_KEY` overrides the key.
- The pack also carries a LAN relay (default port 18326): it authenticates callers with a key this plugin mints, swaps it for the gateway credential at the hop (the credential never leaves the host process), serves only the whitelisted paths above, and refuses request loops. The relay and the plugin's own forward listener (default 18899) still exist in the backend, but the current settings page has no switch for them; they are enabled through the settings API.
- The key is plain text for client configuration only. Do not share it.

## Token savers

Compaction happens before the request leaves the machine, and every step **fails open**: a request shape it does not understand is sent untouched, and a throwing saver never fails the turn.

- **RTK tool-output compaction** rewrites `tool_result` content in place for `git diff / status / log`, `grep`, `find`, `ls`, `tree`, build logs, numbered dumps, search listings and duplicate log lines — 12 filters. Safety boundaries: failed tool results pass through, small bodies are left alone, and a replacement is only made when it is smaller and non-empty.
- **Prompt shaping** offers the Caveman (telegraphic) and Ponytail (YAGNI) families with several levels. All start off, because they change how the assistant writes and stay in the transcript.
- **Five local answers** — quota probe, command prefix, session title, suggestion mode, filepath extraction — answer requests whose answer is already in the body, without spending a provider call.
- **Savings statistics** report bytes before/after, percent saved, blocks compacted and calls measured, stored locally.

## Data and privacy

All state lives in `DSH_HOME/route-models/` (default `~/.dsh/route-models/`):

```text
settings.json                    plugin settings (forward / relay keys, 0600)
stats.json                       usage and request statistics
availability.json                measured availability and egress snapshot
session-map.json                 conversation-to-session mapping
feed.json                        announcement cache
subscriptions/credentials.json   subscription credentials (0600, if used)
egress/mihomo.yaml               outlet configuration (0600, if enabled)
```

Channel credentials and the gateway key live under `DSH_HOME` (or `DSH_CHANNEL_PACK_STATE_DIR`), held by the host credential store and `openai-gateway/api-key`.

**No telemetry is uploaded.** Outbound destinations are limited to:

| Purpose | Destination |
| --- | --- |
| Channel login and inference | each channel's own endpoints (e.g. `api.cline.bot`, `devcloud.cn-north-4.myhuaweicloud.com`, `codearts.huaweicloud.com`), depending on the channel |
| Subscription accounts (if used) | `chatgpt.com`, `auth.openai.com`, `api.anthropic.com`, `cloudcode-pa.googleapis.com`, `oauth2.googleapis.com` |
| Announcements | `raw.githubusercontent.com` → `cdn.jsdelivr.net` → `gh-proxy.com`, in order |
| Egress check | `api.ipify.org` / `ipinfo.io` / `ipapi.co`, only to read this machine's public IP and country code |
| Outlet (if enabled) | the subscription URL you enter; a local mihomo reads it in subscription mode |

## Install

This repository distributes the plugin as a **Release package**:

1. Download and unpack a release package;
2. Plain web profile (`dsh web`):

   ```powershell
   dsh plugin add <unpacked-directory>
   ```

3. Desktop (Electron) profiles are owned by the app; the CLI cannot write them — install from **Settings → Plugins**.
4. Restart or reload the host, then open **Settings → Channel Models**.

Notes:

- The bare same-named package on npm is **not** published by this repository and does not match this tree.
- When a pack or package manager owns the install, set `distribution: 'managed'` in the bundle config or `settings.json`: announcement polling and hot reload stand down and updates belong to the installer, so two writers never touch one directory.
- Do not append an entry to `cordis.patch.yml` by hand: a bundle referenced from `dsh.profile.bundles` already applies its own patch layer, and registering twice fails with `duplicate loader entry id`.
- Copying release files manually means copying the whole package (`adapter/`, `src/`, `locale/`, `vendor/channel-pack/` with its WASM, LICENSE and NOTICE). Entry scripts alone leave channel loading incomplete.

## How it works

```text
index.js                  host half: wiring, API routes, forward/relay lifecycle,
                          announcements and hot reload
client.js                 browser half: hand-written ModuleLoader bundle, no build step
adapter/                  kernel seam: the only place that may import @deepseek-ai/*
src/adapter.js            structural LlmAdapter: route registration, stream decoding,
                          tool-pairing repair
src/core.js               generated runtime bundle (built from src/core/, do not edit)
src/store.js              private JSON stores, settings defaults, stats migration
src/channel.js            channel-model stream adapter
src/subscriptions.js      subscription sidecar: credential normalisation, quota, refresh
src/subscription-adapter.js / subscription-completion.js
                          subscription rows -> catalog and completion stream
src/forward.js            standalone OpenAI-compatible listener (plus Anthropic Messages)
src/chan-relay.js         LAN relay for the channel gateway (own key + path allowlist)
src/egress.js             outlet: subscription mode (local mihomo) or a single proxy
src/token-saver/          compaction pipeline: prompt injection -> tool-output compaction
src/local-optimize.js     the five local answers
src/trust.js              request trust fence for the plugin's routes
src/feed.js               announcement feed: multi-source failover, validation, cache
src/reload.js             self hot reload: cache purge -> re-import -> re-register -> rollback
vendor/channel-pack/      account-channel implementations (MIT, see NOTICE)
```

Design decisions worth knowing:

- **One adapter, two routes.** The model picker is grouped strictly by provider route, so "usable" and "region-limited" can only be expressed as two routes; the client drops empty groups on its own.
- **Structural adapter, no `@deepseek-ai/dsh-llm` import.** The kernel never checks `instanceof`, so duck typing is enough, and one code base spans several kernel patch versions.
- **Private JSON stores instead of the settings seam.** The settings registration API differs between kernels; private stores behave identically and keep keys in `0600` files.
- **Savings run at a single choke point and fail open.** Both the adapter dispatch and the local gateway pass through `payloadFor()`, so every lane is compacted, and an error passes the original text through.
- **The body decides what a response is, not `Content-Type`.** The first bytes are sniffed and replayed into the stream, so a lying header cannot discard a whole turn.

## Known limitations and current status

This repository is converging from a "free-model plugin" into an **account-channel manager**, so the following are **removed** and old docs and announcements about them no longer apply:

- the anonymous free lane (OpenCode Zen), the Kilo free pool, and the EAC co-paid lane (including GitHub authorization and sealed credentials);
- the aggregate lane and provider registry, and combo chains;
- in-app upgrades and the signed-manifest chain (updates belong to the host or installer);
- the standalone local service and the Windows desktop shell (`packages/` is gone).

Also:

- The subscription backend (Codex / Claude / Gemini / custom API credential import, quota queries, token refresh) is still in the tree, but its **management UI was not reconnected** after this round's lane removal, so it cannot be used from the settings page yet. The plugin's own `Route Models` group is therefore usually empty; models are advertised by the channel pack under its own provider groups.
- The settings page and copy keys still carry old naming (`EAC router`, free lane, EAC). It is UI debt, not a functional regression.
- The card list (11), the pack's provider implementations (more than the cards, including Cline and Gemini) and the vendored source (10 providers) disagree; rebuilding with `npm run channel-pack` drops the channels that exist only in `pack.js`.
- The in-app usage notice states that WorkBuddy and Huawei Cloud channels are not offered, while the channel page still renders their cards from the pack: policy and UI are not yet aligned. Treat the login and call result as the fact.
- Offline suites still include cases for removed lanes, so `npm test` is not fully green right now. Release mode (`--mode release`) runs only the packaging and catalog checks, and the catalog check currently fails because the repository rename is not reflected yet.
- Channel models, quotas and credit policies belong to the platforms and can be throttled or withdrawn; the plugin can only report the failure.
- Responsibility for how accounts are used, and for complying with each platform's terms, rests with the user.

## Development

Requires Node `^22.19.0 || >=24.0.0`. No install step, no runtime dependencies.

```bash
npm test                                  # every offline suite (no network, no quota)
node scripts/test-all.mjs --mode release  # packaging and catalog checks only
npm run typecheck                         # tsc --noEmit
npm run channel-pack                      # rebuild pack.js from vendor/channel-pack/src
node scripts/build-legacy-payload.mjs --check   # byte-check generated src/core.js / src/o2a.js
node scripts/channel-pack-test.mjs        # channel-pack artifact checks
```

`scripts/test-all.mjs` is the runner, with a 60-second deadline per suite. The shared scaffolding points external addresses at closed loopback ports, so offline suites never reach a real platform.
